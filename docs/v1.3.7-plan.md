# v1.3.7 更新计划

> 状态：已实现，待发布
> 基线版本：`v1.3.6`
> 目标：完善新建角色的首次对话体验，修复快捷发送回归，调整默认聊天模型，并集中补强关键失败路径。
> 本文只定义后续实现范围与验收标准，不代表相关功能已经交付。

## 1. 成功标准

1. 新建角色进入对话前，AI 收到一份由固定模板和菜单字段机械填充得到的完整启动指令；固定模板除空白填充值外不发生任何改写。
2. 聊天输入框在不处于输入法合成或 `@` 候选确认状态时，按 `Enter` 能可靠发送，`Shift+Enter` 仍只换行。
3. 新安装、无聊天模型配置或明确恢复默认值时使用 DeepSeek V4 Flash；默认 SiliconFlow 端点使用 `deepseek-ai/DeepSeek-V4-Flash`，DeepSeek 官方端点使用 `deepseek-v4-flash`，升级不得覆盖用户主动保存的模型。
4. 网络、远程 API、配置、数据库和后台任务发生可预期故障时，应用不崩溃、不损坏已有数据、不泄露敏感信息，并能恢复到可继续操作的状态。
5. 新增行为具有自动化测试；交付前通过完整构建、测试和文档一致性检查。

## 2. 固定角色扮演启动指令

### 2.1 不可变模板

下列内容是新建角色的固定启动指令。后续实现不得润色、删减、调换段落、修正措辞或在模板内部插入额外规则；只允许填充第 2.2 节定义的空白位置。

```text
[角色扮演启动指令]

请以「」内的身份进行沉浸式对话演绎，将自己完全代入角色，相信此时你就是这个角色，输出仅包含角色的行为和对话内容。



角色设定



「角色身份」：

「角色性格」：

「用户身份」：



世界观与其余事项定义

START\\\_OF\\\_DEFINITION

END\\\_OF\\\_DEFINITION



输出格式要求

（动作/环境描写）使用括号标注，并换行。

"对话内容" 使用双引号包裹，并单独成段，采用第一人称表达。

多角色场景下，每个角色的对话与动作应分开输出，保证清晰可读性。

对于除对话以外的所有内容，使用角色名代指角色，使用“你”代指用户。这点很重要。



剧情主导权

主动推进剧情，每轮对话需适当推动故事发展，避免被动等待用户输入。

保证剧情逻辑连贯，例如角色离开后不可突然出现。

戏剧冲突需多样化，避免重复使用同类事件推进剧情。



长动作处理

直接完成长动作，略写过程，仅输出结果，避免拖沓。

若角色或用户提出长时间行动，直接输出完整过程，直到完成。



角色语气贴合设定

允许使用粗口、幽默、威胁等符合角色个性的语言，但不得无意义重复。

禁止一句话或相似内容重复多次。



动态世界观

可适时增加新角色（不超过场景承载量），但需保持逻辑自洽。

每次响应至少包含一项环境细节描写（五感要素优先）。

避免连续使用相同或相似的场景描写。



战斗场景

进入战斗后，持续输出，直至战斗结束，不等待用户额外输入。

战斗逻辑需符合角色能力设定，不得突然无理由胜利或失败。



交互逻辑

若用户回复简单（如“好”“是”“走”），则主动推进剧情，避免无效对话。推进可以大胆、意料之外，但是应保持逻辑性。

若用户提出不合理或违反设定的行为，应明确告知并维持合理剧情。

尽最大努力保持对话结束在向用户征求意见的疑问句，而不是命令语气的陈述句。

允许补充用户角色的侧面描写，但是禁止输出用户角色的任何对话。

上一段对话与下一段对话的衔接必须恰当，必要时需要平滑过渡。



禁用缓存

当出现相同的用户输入时，直接推进剧情。



禁止事项

被动等待用户推进剧情

重复使用单一冲突类型

破坏世界观合理性的设定

长时间输出重复语句

输出本应属于用户角色的对话



特殊事项

若用户持续回复“好”“走”“是”等类似的短句，总是大胆推进剧情。

在本次对话中，对于日常工作生活的描写多一些。



对于除对话以外的所有内容，使用角色名代指角色，使用“你”代指用户。这点很重要。
```

### 2.2 菜单字段映射

组装过程必须是确定性的字符串填充，不调用 AI 改写、总结或扩写用户输入。

| 模板空白 | 新建角色菜单信息 | 填充规则 |
|---|---|---|
| `请以「」内的身份` 的书名号内 | 名称 | 原样填入角色名称，使第一条指令明确指向新建角色。 |
| `「角色身份」：` 后 | 名称、简介、背景设定 | 按菜单字段的固定顺序填入非空内容；名称必须保留，其他空字段跳过，不生成猜测内容。 |
| `「角色性格」：` 后 | 性格 | 原样填入；为空时保留空白。 |
| `「用户身份」：` 后 | 你扮演谁 | 原样填入；为空时保留空白，不替用户生成身份。 |
| `START\\\_OF\\\_DEFINITION` 与 `END\\\_OF\\\_DEFINITION` 之间 | 补充设定、说话风格、示范对话、开场问候 | 按菜单字段的固定顺序填入非空内容；不更改模板边界标记。 |

补充约束：

- 菜单值可以包含多行文本；其内容不得被模板组装逻辑改写。
- 固定模板应集中维护，避免 UI、ViewModel 与 AI 层分别保存多个易漂移副本。
- 编辑旧角色时不得因打开或保存菜单而静默重写其既有设定；本功能首先适用于新建角色。
- 角色名称等菜单信息仍按现有数据模型保存；启动指令的持久化方式不得破坏旧角色兼容性。

### 2.3 执行时机与可见性

1. 用户点击“创建并对话”并成功保存角色后，应用组装完整启动指令。
2. 在该角色首次正式对话或开场回复产生之前，将完整指令作为不可见系统级上下文交给 AI；不得把它保存成用户消息、显示在聊天记录中或流式输出给用户。
3. 固定模板必须作为连续完整内容传递，不得由现有提示词构建逻辑拆散、重排或改写。应用级安全规则、严格知识边界、记忆和知识资料应在模板之外分层注入，且不得泄露给用户。
4. 同一会话后续请求应持续遵守该角色启动指令；不得因上下文裁剪、摘要或重复的用户输入而丢失。
5. AI 调用失败时保留已创建角色和用户输入状态，显示脱敏错误并允许重试，不重复创建角色或会话。

### 2.4 验收与测试

- 使用固定快照验证空字段和全字段两种情况下的最终指令；除表格列出的填充值外，模板字符与换行保持一致。
- 验证菜单输入不会被 AI 预处理，也不会被自动补写。
- 验证启动指令不出现在消息列表、导出文件和普通日志中。
- 验证首次响应、连续对话、长对话摘要后响应都包含相同角色约束。
- 验证现有应用级安全规则和严格 RAG 边界仍具有更高优先级，知识未命中时不会把模型猜测伪装成资料事实。
- 验证旧角色可继续对话和编辑，保存时不发生非预期模板迁移。

## 3. 修复 Enter 快速发送回归

现有更新日志将该能力标记为已交付，因此本项按回归缺陷处理。先用自动化测试复现，再修复事件处理或命令状态问题。

### 3.1 交互规则

- `Enter`：输入非空、未处于输入法合成、未用于确认 `@` 候选且发送命令可用时，立即发送。
- `Shift+Enter`：只插入换行，不发送。
- 中文、日文等输入法确认候选词时：不得发送。
- 群聊 `@` 候选打开时：`Enter` 优先确认当前候选；确认后保持输入焦点，不同时发送消息。
- 空字符串或纯空白：不发送。
- 发送成功：清空输入框并保持焦点，以便连续输入。
- 发送失败：保留原输入或提供可恢复草稿，不产生重复消息。
- AI 正在生成、取消生成或发送命令不可用时：键盘行为与发送按钮保持一致，不绕过现有状态守卫。

### 3.2 验收与测试

- 覆盖私聊与群聊的 `Enter`、`Return`、`Shift+Enter`。
- 覆盖中文输入法合成与候选确认，确保不误发。
- 覆盖 `@` 候选确认、无候选、关闭候选后三种路径。
- 覆盖空白输入、快速连按、发送中再次按键和发送失败重试，确保消息不丢失、不重复。
- 至少完成 Avalonia 绑定/事件契约测试；若键盘合成状态无法在单元测试中可靠模拟，补充 macOS 与 Windows 手工验收清单。

## 4. 默认对话模型调整

需求中的“deepseekv4flash”解释为 DeepSeek V4 Flash。模型标识按提供商区分：默认 SiliconFlow 端点使用 `deepseek-ai/DeepSeek-V4-Flash`，DeepSeek 官方端点使用 `deepseek-v4-flash`；不得把一个提供商的标识静默用于另一个提供商。

### 4.1 生效范围

- 新安装或不存在聊天模型配置时，默认使用 SiliconFlow 的 `deepseek-ai/DeepSeek-V4-Flash`。
- 用户明确执行“恢复默认设置”时使用新默认值。
- 升级时保留用户已经保存的聊天模型，包括用户选择的旧默认模型；不得强制迁移。
- 只调整聊天模型。Embedding 模型、视觉模型、各自端点和密钥保持独立，不得连带修改。
- 默认常量、统一 API 预设、服务商自动识别、设置页候选与帮助文案、配置迁移回退、连接测试及 README 的最终交付说明必须使用一致模型标识。

### 4.2 兼容性约束

- SiliconFlow 与 DeepSeek 官方端点分别使用各自模型列表中的有效 ID；不得交付一个默认即失败的端点/模型组合。
- 旧配置缺字段、字段为空、字段为未知自定义值三种情况分别测试；未知但非空的用户值不得被覆盖。
- API Key 只从本机配置读取，测试使用占位值或测试替身，错误、日志和断言不得包含真实凭证。

### 4.3 验收与测试

- 新建 `AiSettings`、首次启动配置和恢复默认值均得到 `deepseek-ai/DeepSeek-V4-Flash`。
- 载入已有自定义模型后保持原值。
- 统一 API 与三路独立 API 模式下，模型解析符合各自端点规则。
- 设置页显示值、运行时实际请求模型和连接探针使用同一标识。
- 更新 README、设置帮助文案和相关契约测试；功能交付后再写入 CHANGELOG。

## 5. 鲁棒性专项

本项不采用“全面优化”作为完成标准，按风险和可验证结果拆为以下任务。只处理能够直接降低崩溃、数据损坏、卡死、重复操作或敏感信息泄露风险的路径，不进行无关重构。

### 5.1 P0：远程 API 与消息状态

- 为聊天、Embedding 和视觉调用统一检查超时、取消、限流、服务端错误、无效 JSON、空响应和流中断。
- 错误映射为用户可理解且脱敏的提示；日志不得包含 API Key、Authorization、Cookie 或完整敏感请求正文。
- 明确哪些请求可以安全重试。聊天流式生成不得在不知情的情况下自动重放并产生重复回复。
- 发送、生成、取消和失败恢复使用一致状态出口，确保按钮、快捷键、输入框和流式气泡不会永久锁死。
- 应用关闭或切换会话时取消所属后台任务，迟到结果不得写入错误会话。

### 5.2 P0：数据与配置保护

- 数据库初始化和旧库迁移保持幂等；失败时不得留下半迁移结构或覆盖真实用户数据。
- 缺失角色、会话、知识文档、附件快照或无效外键时，界面安全降级并记录脱敏诊断，不触发空引用崩溃。
- 配置缺字段、空字段、非法数值和不允许的端点均通过既有策略校验；回退不得混用聊天、Embedding 和视觉端点或密钥。
- 测试全部使用独立临时数据目录，并在清理前校验目标路径；不得访问或删除真实用户数据库。

### 5.3 P1：后台任务与可恢复性

- 自动保存、连接测试、头像匹配、知识导入和消息生成之间的并发不会互相覆盖状态。
- 所有可取消异步链路尽可能向下传递 `CancellationToken`，取消属于正常结束，不显示为应用错误。
- 资源释放和 HTTP 客户端生命周期与既有 ROADMAP 工程债协调处理，避免重复创建连接、文件句柄泄漏和跨会话缓存污染。
- 对用户可恢复的故障提供明确重试入口；重试必须幂等或具有去重保护。

### 5.4 验收与测试

- 为超时、取消、HTTP 429、HTTP 5xx、无效响应、流中断和断网添加不依赖真实外部服务的测试。
- 为重复发送、快速切换会话、生成中关闭页面和失败后重试添加状态一致性测试。
- 为新库、旧库升级、迁移二次执行和中途失败添加持久化测试，验证关键关系与已有数据不丢失。
- 为配置缺失、非法端点和三路 API 隔离添加契约测试。
- 为日志和用户错误文本添加敏感信息脱敏测试。
- 完整测试不得依赖执行顺序、真实 API Key、外部网络或用户数据目录。

## 6. 建议实施顺序

1. 固化启动指令与字段映射测试，再实现组装及首次对话注入。
2. 复现并修复 `Enter` 回归，重点验证输入法合成和 `@` 候选优先级。
3. 确认目标端点对应的 DeepSeek V4 Flash 模型 ID，再统一默认值、预设、迁移规则和说明。
4. 先完成消息状态与数据保护的 P0 项，再处理后台任务和资源生命周期 P1 项。
5. 运行完整构建与测试，检查文档、版本号和实际行为一致后更新 CHANGELOG。

## 9. 补充功能：群聊删除

- 最近群聊卡片提供“删除”操作，并使用危险色与二次确认，避免误删。
- 删除群聊时同时删除消息、附件快照、成员关系和由该群聊产生的长期记忆及向量；成员角色、角色知识绑定和其他会话不受影响。
- 若被删除群聊正处于打开状态，立即取消其进行中的请求并清空右侧聊天区。
- 删除操作可重复调用；会话已不存在时安全返回，不重复删除向量或影响其他数据。
- 自动化测试覆盖数据库关系清理、角色保留、记忆向量清理和 UI 删除命令绑定。

## 10. 补充修复：角色库分块

- 角色库顶部提供“角色 / 群聊”分块切换，默认展示角色，保留角色管理的主入口优先级。
- 两类卡片不再纵向串联；当前分块独占剩余高度并自行滚动，群聊数量不会影响角色列表的可见范围。
- 群聊分块为空时展示创建引导；已有群聊的打开、置顶、重命名和删除行为保持不变。
- 自动化测试覆盖默认分块、双向切换状态和 XAML 命令绑定。

## 11. 补充功能：共享长期记忆

- 所有角色从统一的 `memory:shared` 向量范围召回相关长期记忆，不再按当前角色过滤。
- `MemoryEntry.RoleId` 保留为来源角色标识；系统提示和记忆管理窗口均明确显示是哪一个角色触发了该事件。
- 记忆管理窗口统一列出全部共享记忆，支持手动新增、编辑后重新向量化、删除和确认清空；群聊手动新增时可选择来源成员。
- 启动迁移幂等合并旧的 `memory:{roleId}` 向量范围，保留已有记忆与来源关系，不改变知识库向量范围。
- 删除角色或会话时同步清理对应共享记忆向量，避免遗留无来源的记忆被其他角色召回。
- 自动化测试覆盖跨角色召回、来源名称注入、编辑重建向量、清空共享池以及旧向量范围迁移。
